# Обновление интерфейса LMS одной командой

На рабочем сервере `/opt/lms`, frontend `/var/www/lms/client-dist`, Node 24 `/opt/node24`.

После слияния PR со **строго клиентскими изменениями** запускать от root:

```bash
bash /opt/lms/deploy/update-frontend.sh
```

Важно: первый раз новый файл ещё нужно получить в локальную копию репозитория через `git fetch origin main && git merge --ff-only origin/main`, затем выполнить команду. После первого раза скрипт сам получает изменения из GitHub.

Скрипт отказывается обновлять рабочую копию с локальными изменениями, с расхождением истории или если среди новых коммитов встречаются серверный код, миграции, корневые зависимости и любые другие файлы кроме `client/` и документации. В таком случае нужна **отдельная проверенная процедура полного обновления** с backup PostgreSQL и загрузок. Не обходить блокировку через `git reset --hard`.

Скрипт использует Node.js 24, собирает только `client`, копирует предыдущую статику в каталог `/var/backups/lms/frontend-<UTC>`, публикует новую сборку, проверяет HTTPS и пытается откатить frontend при ошибке публикации. Он не является полноценным атомарным деплоем и не выполняет проверку авторизованных страниц. Проверить дашборд в браузере после запуска обязательно.

Старый `deploy/deploy.sh` не применять для нынешней VDS: в нём присутствуют `git reset --hard` и проверка неверного порта 3000.
