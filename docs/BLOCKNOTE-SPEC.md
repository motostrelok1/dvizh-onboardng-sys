# SPEC: визуальный блочный редактор уроков BlockNote

Статус: **решено внедрять BlockNote** (2026-10-15); внедрение по этапам, пока не завершено. Основа: React 18, Fastify, PostgreSQL, текущий `lessons.text_content` и существующее файловое хранилище. Не путать с Notion SaaS — используем библиотеку в собственном интерфейсе.

## 1. Цель

Администратор оформляет урок из блоков (как в Notion); сотрудник видит готовую страницу без возможности редактирования. Бесплатная self-hosted реализация: выбирать только совместимые open-source пакеты/плагины, фиксировать версии и лицензии при установке. Не подключать платный облачный сервис, сторонний редактор с передачей контента, AI/API-ключи и лицензируемые функции без отдельного решения. **Лицензии:** @blocknote/react и базовые пакеты публикуются под MPL-2.0 (это не MIT); пакеты @blocknote/xl-* используют GPL-3.0 либо коммерческую лицензию. При интеграции нужно выполнить обязательства MPL-2.0 и проверить все зависимости; XL не подключать без отдельного согласования. Источники: https://www.blocknotejs.org/docs/getting-started и https://www.npmjs.com/package/@blocknote/react .

## 2. UX редактора

- Вместо plain textarea — BlockNote в каждом открытом уроке; по нажатию `/` доступно меню блоков.
- Заголовки H1–H3, абзацы, жирный/курсив/подчёркнутый/зачёркнутый текст, цвет и выделение, ссылки, маркированные/нумерованные списки, чек-листы, цитаты, кодовые блоки, разделитель, таблица (если доступна в выбранной бесплатной версии).
- Перетаскивание блоков, undo/redo, hotkeys, вставка из буфера.
- Кнопка выбора эмодзи с доступным локальным picker; системные Unicode emoji допустимы в любом тексте, поиск и категории — желательны.
- Картинки: файл, drag-and-drop, paste; допустимые MIME и максимальный размер явно отображаются; загрузка с прогрессом/ошибкой, удаление/замена, alt-текст и подпись; безопасное изменение размера в рамках поддерживаемых возможностей. Галерея/колонки — отдельный этап, не считать готовыми автоматически.
- Учебные блоки: `Важно`, `Совет`, `Предупреждение`, `Пример`, `Запомните` с фиксированными семантическими стилями, а не произвольным HTML.
- Редактор встраивается в существующие модуль/урок, не ломая drag-and-drop уроков/модулей и панели тестов.
- Доступность: keyboard navigation, focus, подписи на русском, телефоны 320 px и больше, light theme LMS; editor не должен монтироваться в свёрнутых уроках, если это дорого по памяти.
- Сохранение: debounce ~1–2 с, статус `изменения / сохранение / сохранено / ошибка`, защита от ухода с несохранёнными изменениями, явное `Сохранить` и повторная попытка; конфликт одновременных изменений двух администраторов нельзя молча перетирать.

## 3. Данные и миграция

- **Предлагаемый контракт v1:** структурированный JSON BlockNote хранится отдельно от plain text в `lessons.content_blocks jsonb NULL`; `content_schema_version SMALLINT` или версионный envelope; индекс/новая таблица только после оценки миграции. На чтение выдавать `contentBlocks` (структурированный документ) и legacy `textContent` для обратной совместимости.
- Старые уроки с `text_content` автоматически показывать как один или несколько обычных абзацев **без записи в БД при чтении**. При первом сохранении нового редактора писать JSON; старый текст сохранять как legacy fallback до подтверждённого переключения.
- Валидировать сервером размер JSON, глубину, число блоков, типы/attrs, ссылки, связанные media ID. Отказывать неизвестному типу/схеме. Никогда не доверять HTML из браузера и не хранить произвольные script/iframe.
- JSON→read-only renderer для сотрудника, админского предпросмотра и демотеста; одинаковая стилизация, корректная обработка отсутствующих ссылок. Не использовать `dangerouslySetInnerHTML` на недоверенном содержимом.
- Изменять админские API создания/редактирования урока, дерево курса и API сотрудника согласованно; права admin на запись, course-access на чтение; админский preview не создаёт учебных событий/попыток.
- Продумать `content_revision` для Optimistic Concurrency (compare-and-swap, 409 conflict) до включения автосохранения.

## 4. Изображения и безопасность

- Не вставлять base64/data URL изображения в БД, не допускать произвольные внешние URL по умолчанию. Файлы — в существующем `UPLOAD_DIR`, **не в публичном webroot**.
- Отдельные admin upload и authenticated preview/lesson GET endpoint с той же проверкой роли и доступа к уроку, лимитами, проверкой magic bytes, защитой от symlink/path traversal, no-store, nosniff и безопасным Content-Type.
- Разрешить сначала JPEG/PNG/WebP (SVG/GIF не включать до отдельного аудита). Квоты и существующие лимиты параллельной загрузки/свободного диска распространяются на inline media.
- Ссылки в JSON — по идентификатору медиа, а не абсолютному пути или токену. Удаление урока/модуля/курса включает очереди файловой очистки. Ошибка загрузки не должна вставлять битую ссылку.
- Персональные данные/токены не выводить в client logs или телеметрию, CSP и XSS тесты обязательны.

## 5. Этапы и критерии

- **BN-01. Исследование и подготовка зависимостей** — зафиксировать версии BlockNote, React18-совместимость, лицензию, сборку и PWA размер, провести audit; отдельный PR с package-lock. Автодеплой изменений lockfile закономерно откажет: нужен согласованный полный rollout или поддержка отдельной безопасной процедуры.
- **BN-02. API/БД и совместимость** — отдельная миграция, DTO и серверная строгая валидация JSON, сохранение legacy, роли, конкурирующие редакторы; интеграционные тесты и восстановление. Миграции не выпускать обычным auto-deploy.
- **BN-03. Редактор** — интегрировать BlockNote, панель, горячие клавиши, русский UX, plain-text import, структурированное сохранение и статусы.
- **BN-04. Read-only просмотр** — сотрудник и предпросмотр администратора используют общую визуализацию; тесты/аналитика не изменяются при preview.
- **BN-05. Фото и эмодзи** — авторизованные загрузки, clipboard/drop, alt/caption, лимиты, picker.
- **BN-06. Учебные блоки/удобство** — callouts и мобильные формы, auto-save/409, keyboard/accessibility, undo/redo.
- **BN-07. Приёмка** — desktop/mobile, импорт прежних уроков, длинные документы, таблицы, изображения, XSS, разрывы сети, повторные открытия и CI browser E2E.

**Сейчас не реализовано:** новая библиотека, JSON storage, inline фото, rich renderer и автосохранение. Эти статусы изменять только после реальных проверок.
