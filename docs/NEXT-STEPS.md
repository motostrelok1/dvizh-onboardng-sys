## Как работаем

После выбранного приоритета: изучаем код и критерий готовности → отдельная
ветка/PR → зелёные build + integration → merge. Изменения без
миграций/lockfile автоматически деплоятся в `main`; при изменениях
БД/зависимостей необходим отдельный согласованный runbook. После деплоя
фиксируем наблюдаемую приёмку в PROGRESS/аудите, не выдавая CI за полный E2E.

**Рекомендация следующей задачи:** OPS-01 (восстановление и регулярный
backup) параллельно с UI-01/QA-01, чтобы не копить изменения без защиты данных.
